# Platform overview

For product vision, start with [Veridian Motion](/veridian-motion/product).
This page lists what is **built today** on the Lovable build (TanStack Start +
Supabase), running on **synthetic data**. Modules are **additive and
feature-flagged**.

<Note>
  **Non-diagnostic.** AI and program content organize the patient's own data and
  teach self-care; a **licensed clinician** (PT/PA as applicable) reviews before
  clinical materials reach a patient. **HIPAA-aligned, not HIPAA-certified.**
</Note>

## What it is

| Surface | Users | Purpose |
| --- | --- | --- |
| **Patient portal (kiosk)** | Patients (facility ID + PIN) | MSK intake, medical intake, Precision Rehab, Chess Wellness, messaging, approved plans |
| **Provider dashboard** | Staff (`pt`, `admin`, `officer`, `warden`, `it_admin`, …) | Roster, programs, review, messaging, analytics, multi-facility |
| **Officer wellness portal** | Staff participants | Separate confidential employee wellness portal |

TanStack Start (React 19), installable **PWA**, USWDS-aligned UI, Supabase
(Postgres, Auth, Storage) via Lovable Cloud.

## Built today

### Accounts, roles & security

- **Staff:** email + password + **TOTP MFA** (enforced per deployment)
- **Patients:** facility **Patient ID + PIN** (no self sign-up)
- Roles include `pt`, `admin`, `officer`, `warden`, `it_admin`, and
  `wellness_participant` (employee wellness)
- **RLS** on every table; facility membership helpers
- **Append-only, hash-chained audit log**; field-level PHI encryption (AES-256-GCM)
- **Multi-facility isolation** — staff can **switch facilities**; `warden` sees
  **operational** data only (**no clinical PHI**)

### Programs (license-gated)

Shared [Programs & licensing](/veridian-motion/programs-and-licensing) spine:
entitlements, seat caps, enrollments, monthly billing snapshots, invoice PDF
support. **Contract-first — no credit cards.**

### Operations

- **Admin console:** Programs & Access, pricing calculator, **mass import**
  (staff + patients), per-patient and bulk enrollment, billing snapshots,
  legal-forms console
- **Secure messaging** with **safety screening** and admin **Communication Record**
- **Admin analytics** — facility engagement / value reporting (measured vs
  clearly labeled estimated figures; no individual PHI)
- **Legal Terms** — versioned acceptance at registration
- **Offline-capable** where it matters (chess engine, puzzles, rehab) on locked
  facility networks

## Design principles

- **Non-diagnostic** — clinician review before clinical content reaches patients
- **Safety-gated** — red-flag screens route worrying cases toward in-person sick call
- **Additive + flag-gated** — modules ship behind flags, off until cleared
- **Offline where it matters** — no external chess/rehab API calls required for
  core program loops

## What it is not (current public release)

- **Not a diagnosis tool**
- **Not HIPAA-certified, CJIS-authorized, or FedRAMP-authorized**
- **Not SSO, JMS, EHR, partner API, or live video** — see [Roadmap](/veridian-motion/roadmap)
- **Not medical coding / insurance billing** (program seat licensing ≠ medical billing)
- **Not AI behavioral-health, psychiatric, mood, or emotional-assessment modules**
  — those are **not documented** in public docs and remain disabled

## Compliance & synthetic data

Current Lovable builds use **synthetic data only** and will not hold real PHI.
Before a real pilot: owned Supabase (HIPAA add-on + BAA), compliant host, BAA-
covered/self-hosted AI screener where required, counsel-finalized Terms/MSA/BAA,
IRB determination (program-evaluation framing), and clinical sign-offs. See
[Security overview](/security/overview).
