# Data model & privacy

Veridian Motion uses **row-level security (RLS) on every table**, scoped by
**facility membership**, plus **field-level PHI encryption** (AES-256-GCM where
PHI) and a **hash-chained audit log**.

**HIPAA-aligned, not HIPAA-certified.** A **BAA** is required before production PHI.
Current Lovable builds use **synthetic data only**.

## Core clinical / portal entities

| Entity | Description | PHI |
| --- | --- | --- |
| **Patient** | Enrolled — Patient ID, facility membership | Yes |
| **Assessment** | MSK portal submission (body map, complaint, questionnaire, photos, AI plan) | Yes |
| **Photos** | Up to four posture images | Yes |
| **Exercise plan** | AI draft and clinician-approved plan | Yes |
| **Clinician notes** | Clinical notes; optional share-with-patient flag | Yes |
| **Messages** | Append-only clinician ↔ patient thread (safety-screened) | Yes |
| **Communication Record** | Admin-only immutable messaging export | Yes (controlled) |
| **Staff roles** | `pt`, `admin`, `it_admin`, `officer`, `warden`, `bh_clinician`, `wellness_participant` + facility membership | Metadata |
| **Audit log** | Hash-chained actions (no PHI in payload) | No PHI in logs |

## Medical Intake

| Entity | Description | PHI |
| --- | --- | --- |
| **`medical_profiles`** | One-time history, meds + side-effect screen, allergies, surgical, social + red-flag markers | Yes |

Emergency contact is **intentionally omitted** (facility security).

| Table group | Purpose | PHI |

| `rehab_modules`, `rehab_techniques` | Course / technique content | Content |
| `rehab_safety_flags` | Safety-screen flags that stop a session | Yes when tied to a session |
| `rehab_certifications` | Certificate of Competency artifacts | Yes |
| `rehab_sessions` | Guided self-treatment session logs | Yes |

## Chess Wellness (`chess_*`)

| Table group | Purpose | PHI / sensitivity |
| --- | --- | --- |
| `chess_games` | On-device play vs engine | Patient activity |
| `chess_puzzles`, `chess_puzzle_attempts` | Tactics puzzles and attempts | Patient activity |
| `chess_seasons`, `chess_progress` | Solo ranking / tiers / seasons | Patient activity |
| `chess_challenge_runs` | Daily / Rush / Ladder runs | Patient activity |
| `chess_assignments` | Instructor-assigned activities | Yes (assignment) |
| `chess_lessons`, `chess_lesson_progress` | Academy curriculum progress | Patient activity |
| `chess_academy_certs` | Certificate of Completion | Yes |

No patient-vs-patient matchmaking or chat tables.

## Programs & licensing

| Entity | Purpose |
| --- | --- |
| `programs` | Catalog of licensable programs |
| `program_entitlements` | Per-facility license, seat cap, contract price |
| `program_enrollments` | Per-patient seat |
| `program_billing_snapshots` | Immutable monthly metering |
| `program_usage_events` | Usage events for metering / audit |

Access rule: facility has an **active entitlement** AND patient has an **active
enrollment** within the seat cap. See

## Multi-facility isolation (rolling out)

When enabled, each facility's patients and staff are isolated through **RLS** by
facility membership (`private.has_role()`, `private.is_facility_member()`).
**`warden` / `officer`** see operational data only — **no clinical PHI**.

## Row-Level Security (summary)

| Actor | Access |
| --- | --- |
| **Patient** | Own record only; plans after clinician approval; notes if shared |
| **PT** | Assigned patients in their facility |
| **Admin** | Roster, enrollment, programs, Communication Record, analytics (facility-scoped) |
| **Officer / Warden** | Operational metrics and escalations — **no clinical PHI** |
| **IT admin** | Security/compliance views per role |
| **Wellness participant** | Own employee wellness data only |
| **BH clinician** | Reserved — BH module not publicly available |

## Audit log

Hash-chained entries for: enroll, assign, review/approve, notes, roles, MFA
reset, messages, Communication Record access, program enrollment changes, legal
acceptances. No clinical content in audit payload.

## Agency vs. application

| Topic | Veridian Motion | Agency |
| --- | --- | --- |
| RLS, encryption, audit log | Yes | — |
| BAA | Design supports | Execute |
| CJIS / FedRAMP / GovCloud hosting | — | Yes |
| MDM and physical kiosk controls | App hardening | Device management |
