# Data model & privacy

Veridian Motion uses **row-level security (RLS) on every table**, scoped by
**facility membership**, plus **field-level PHI encryption** (AES-256-GCM) and
a **hash-chained audit log**.

**HIPAA-aligned, not HIPAA-certified.** A **BAA** is required before production PHI.
Current Lovable builds use **synthetic data only**.

## Core entities

| Entity | Description | PHI |
| --- | --- | --- |
| **Patient** | Enrolled — Patient ID, facility membership | Yes |
| **Assessment** | Portal submission (body map, complaint, questionnaire, photos, AI plan) | Yes |
| **Photos** | Up to four posture images | Yes |
| **Medical profile** | One-time medical intake + red-flag markers | Yes |
| **Rehab sessions / routines / certs** | Precision Rehab logs and competency artifacts | Yes |
| **Chess progress / assignments / certs** | Chess Wellness activity (solo; no patient-vs-patient) | Yes (controlled) |
| **Program entitlements / enrollments** | Facility licenses, seat caps, patient seats | Metadata / billing |
| **Billing snapshots** | Immutable monthly metering | Metadata |
| **Exercise plan** | AI draft and clinician-approved plan | Yes |
| **Clinician notes** | Clinical notes; optional share-with-patient flag | Yes |
| **Messages** | Append-only clinician ↔ patient thread (safety-screened) | Yes |
| **Communication Record** | Admin-only immutable messaging export | Yes (controlled access) |
| **Legal acceptances** | Versioned Terms acceptance timestamps | Metadata |
| **Staff roles** | `pt`, `admin`, `officer`, `warden`, `it_admin`, `wellness_participant` + facility membership | Metadata |
| **Audit log** | Hash-chained actions (no PHI in payload) | No PHI in logs |

## Multi-facility isolation

- Each facility's **patients and staff** are isolated through **RLS** by
  **facility membership** (`private.has_role()`, `private.is_facility_member()`)
- **`pt`** — clinical data for assigned patients **within their facility**
- **`officer` / `warden`** — **operational** data only — **no clinical PHI**
- **`admin`** — operational and clinical admin per facility assignment
- Staff with multiple facilities **switch context**; queries remain facility-scoped

## Program access

A patient may use a licensed program only when the facility holds an **active
entitlement** and the patient holds an **active enrollment** within the seat
cap. See [Programs & licensing](/veridian-motion/programs-and-licensing).

## Row-Level Security (summary)

| Actor | Access |
| --- | --- |
| **Patient** | Own record only; plans after clinician approval; notes if shared |
| **PT** | Assigned patients **in their facility** |
| **Admin** | Roster, enrollment, programs, Communication Record, analytics (facility-scoped) |
| **Officer / Warden** | Operational metrics and escalations — **no clinical PHI** |
| **IT admin** | Security/compliance views per role |
| **Wellness participant** | Own employee wellness data only |

## Communication Record

- **Admin-only**, **immutable** export of messaging threads (PDF)
- **Every access** audit-logged in the hash-chained log
- Not available to **`warden`**, **`officer`**, or **`pt`** by default

## Audit log

Hash-chained entries for: enroll, assign, review/approve, notes, roles, MFA
reset, messages, **Communication Record access**, program enrollment changes.
No clinical content in audit payload.

## Agency vs. application

| Topic | Veridian Motion | Agency |
| --- | --- | --- |
| RLS, encryption, audit log | Yes | — |
| BAA | Design supports | Execute |
| CJIS / FedRAMP / GovCloud hosting | — | Yes |
| MDM and physical kiosk controls | App hardening | Device management |
