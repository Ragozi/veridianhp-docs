# Role permissions

Veridian Motion uses **role-based access** plus **row-level security (RLS)**
scoped by **facility membership**. Staff with access to multiple facilities can
**switch between facilities** in the dashboard.

<Note>
  Staff require **email + password** and **TOTP MFA** (enforced per deployment
  via `MFA_ENFORCED`). Roles are granted only by an **admin**.
</Note>

## Staff roles (public docs)

| Role key | Purpose |
| --- | --- |
| `pt` | Clinical review and patient messaging |
| `admin` | Enrollment, programs/licensing, roles, analytics, Communication Record |
| `officer` | Facility operational support per policy — **no clinical PHI by default** |
| `warden` | Operational oversight only — **no clinical PHI** (minimum-necessary) |
| `it_admin` | Security / compliance administration |
| `wellness_participant` | Officer & Staff Wellness portal participant (employee wellness) |

Patient kiosk access is separate (Patient ID + PIN) — not a staff role.

## Role summaries

### Physical therapist (`pt`)

Primary **clinical user** for a facility. Reviews assigned assessments,
Precision Rehab session logs, and medical-intake flags as applicable. Approves
plans, notes, messages patients. Clinical data scoped by facility membership
and assignment.

### Administrator (`admin`)

**Operational owner** — enrollment (manual and mass import), program
entitlements and seats, bulk program enrollment, roles, MFA reset, Communication
Record, admin analytics, legal-forms console, billing snapshots.

### Officer (`officer`)

**Facility operational support** per agency policy. Does **not** receive clinical
PHI by default (assessments, AI output, plans, message bodies).

### Warden / facility oversight (`warden`)

**Operational visibility only** — enrollment counts, confirmation that care
workflows are active, and **safety escalations**. **No clinical PHI.** HIPAA
**minimum-necessary** by design.

### IT admin (`it_admin`)

**Technical administration** — security settings, compliance tooling, MFA
break-glass. No clinical review or patient enrollment by default.

### Wellness participant (`wellness_participant`)

Access to the confidential [Officer & Staff Wellness](/veridian-motion/officer-staff-wellness)
portal as an **employee** participant — not a patient clinical role.

## Patient (kiosk)

| Action | Allowed |
| --- | --- |
| Sign in with Patient ID + PIN | Yes |
| Complete MSK / medical intake when enabled | Yes |
| Use enrolled programs (rehab, chess, …) | Yes |
| View approved plan after clinician approval | Yes |
| Reply in secure messaging threads | Yes |
| View AI output before clinician approval | **No** |
| Self sign-up | **No** |

## Multi-facility isolation

- Each facility's patients and staff data are isolated through **RLS** by
  **facility membership** (`private.has_role()`, `private.is_facility_member()`)
- Clinicians see clinical data for **their facility only** (per assignment)
- Cross-facility patient access is denied at the database layer

## Enforcement

1. **Application UI and API** — role checks on staff actions
2. **Row-level security** — facility-scoped queries
3. **Hash-chained audit log** — sensitive actions; Communication Record access
   is audit-logged
4. **Program entitlement checks** — seat-capped enrollments
