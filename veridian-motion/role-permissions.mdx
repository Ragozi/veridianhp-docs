# Role permissions

Capability matrix by role. For authentication, provisioning, and multi-facility
membership, see [Roles and access](/veridian-motion/roles-and-access) — these
pages are intentionally separate.

Veridian Motion uses **role-based access** plus **row-level security (RLS)**
scoped by **facility membership**. Permissions below describe the **built**
matrix; multi-facility switching and some program modules are **rolling out** —
confirm activation for your deployment.

<Note>
  Staff require **email + password** and **TOTP MFA** (enforced per deployment).
  Roles are granted only by an **admin**.
</Note>

## Staff roles

| Role key | Purpose |
| --- | --- |
| `pt` | Clinical review (MSK, Precision Rehab, Medical Intake as applicable) |
| `admin` | Enrollment, program licensing/seats, roles, analytics, Communication Record |
| `it_admin` | Security / compliance administration |
| `officer` | Facility operational support — **no clinical PHI by default** |
| `warden` | Operational oversight only — **no clinical PHI** (minimum-necessary) |
| `bh_clinician` | Reserved for future Behavioral Health workflows — **BH product not publicly available** (WOPR pending) |
| `wellness_participant` | Officer & Staff Wellness portal participant (employee wellness) |

Patient kiosk access is separate (Patient ID + PIN) — not a staff role.

## Role summaries

### Physical therapist (`pt`)

Primary **clinical user**. Reviews assigned MSK assessments, Precision Rehab
session logs / routine completions, and Medical Intake flags. Approves plans,
notes, messages patients. May assign Chess activities per facility policy.

### Administrator (`admin`)

**Operational owner** — bulk roster import, program entitlements and seats,
bulk/per-patient enrollment, roles, MFA reset, Communication Record, admin
analytics, legal-forms console, billing snapshots.

### Officer (`officer`)

**Facility operational support** per agency policy. Does **not** receive clinical
PHI by default.

### Warden (`warden`)

**Operational visibility only** — enrollment counts, workflow activity, safety
escalations. **No clinical PHI.** HIPAA **minimum-necessary** by design.

### IT admin (`it_admin`)

**Technical administration** — security settings, compliance tooling, MFA
break-glass.

### BH clinician (`bh_clinician`)

Role key reserved for future BH workflows. **Behavioral Health is not a public
product** pending WOPR legal clearance — see [Roadmap](/veridian-motion/roadmap).

### Wellness participant (`wellness_participant`)

Access to the confidential [Officer & Staff Wellness](/veridian-motion/officer-staff-wellness)
portal as an **employee** participant.

## Patient (kiosk)

| Action | Allowed |
| --- | --- |
| Accept Terms at first login | Yes (required) |
| Sign in with Patient ID + PIN | Yes |
| Complete MSK / Medical Intake when enabled | Yes |
| Use enrolled programs (rehab, chess, …) | Yes |
| View approved plan after clinician approval | Yes |
| Reply in secure messaging threads | Yes |
| View AI output before clinician approval | **No** |
| Self sign-up | **No** |

## Enforcement

1. **Application UI and API** — role checks
2. **Row-level security** — facility-scoped queries
3. **Hash-chained audit log** — sensitive actions; Communication Record access logged
4. **Program entitlement checks** — seat-capped enrollments
